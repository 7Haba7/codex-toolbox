# Состояние codex-toolbox

Фильтр по буквальному пути добавлен в tools/context.py. Проверки семи профилей и сводки Git прошли локально на Python 3.12. Команда для повторения: `python3 -m unittest discover -s tests -v`. Конфигурация GitHub Actions находится в .github/workflows/check.yml.

На ревизии `3df61ba` отдельному помощнику явно передали профиль `.codex/agents/explorer.toml`. Он нашёл действовавший тогда лимит в 4000 символов. Теперь `tools/context.py` использует 8 000 000 000 символов по умолчанию. При проверке скрипт вывел сводку из 6329 символов целиком, а с `--limit 4000` сократил её до 4000 символов. Оба теста из `tests/test_toolbox.py` прошли.

Автоматический выбор роли проверен в Codex CLI 0.172.0-alpha.2 на ревизии `f53f912`. Локальный тестовый сервер имитировал ответы модели. Он запросил `spawn_agent` с `agent_type="explorer"`, без пути к профилю и без текста его инструкций. CLI завершил вызов, создал отдельный поток и включил в инструкции помощника точный текст из `.codex/agents/explorer.toml`. В каталоге ролей CLI были видны описания всех семи проектных профилей.

В контрольной копии той же ревизии исключили только `.codex/agents/explorer.toml`. Вызов встроенного `explorer` по-прежнему завершился, но проектные инструкции исчезли из запроса помощника. Оба теста `python3 -m unittest discover -s tests -v` также прошли.

При следующей задаче можно вызывать проектного `explorer` по имени в Codex CLI. Запуск в пользовательском Codex Cloud остаётся отдельной проверкой. В этой сессии сервис запросил повторный вход.
